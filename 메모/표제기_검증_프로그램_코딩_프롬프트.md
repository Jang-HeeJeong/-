# 표제기 자동 검증 프로그램 — 클로드 코드 프롬프트 가이드

---

## 사전 준비: 클로드 코드에 넘길 파일

| 파일 | 용도 | 비고 |
|------|------|------|
| `의약품_표준제조기준.json` | 표제기 원본 데이터 (5개 장) | 이미 완성됨 |
| 기존 엑셀 검증파일 (선택) | 검증 로직 참고용 | 아래 프롬프트로 토큰 절약 가능 |

## STEP 0. 기존 엑셀 로직 분석 (선택 — 엑셀 올릴 경우)

> **엑셀 올릴 때 아래 프롬프트를 먼저 사용**하면 토큰을 크게 절약합니다.
> 엑셀 전체를 읽지 않고, 구조와 수식 패턴만 파악합니다.

```
이 엑셀 파일은 의약품 표준제조기준(표제기) 검증용 파일이야.
전체 데이터를 읽지 말고, 다음만 정리해줘:

1) 시트 목록과 각 시트의 역할 (1줄 요약)
2) 입력 셀 위치와 입력 항목 (성분명, 함량, 제형, 연령 등)
3) 핵심 검증 수식 패턴 3~5개만 (어떤 셀이 어떤 조건으로 판단하는지)
4) 결과 출력 형태 (적합/부적합 표시 방식)
5) 효능효과·사용상주의사항이 어떤 로직으로 생성되는지

결과를 마크다운 표로 정리해줘. 데이터값은 읽지 마.
```

## STEP 1. 프로젝트 초기 세팅

```
다음 조건으로 웹 애플리케이션 프로젝트를 세팅해줘.

[기술 스택]
- HTML + Vanilla JS (단일 파일, 프레임워크 없음)
- 표제기 데이터: 의약품_표준제조기준.json (같은 폴더에 위치)

[이유]
- 단일 HTML 파일이면 별도 빌드/서버 없이 바로 실행 가능
- JSON을 fetch로 로드하면 데이터 업데이트가 용이
- 의존성 0 → 버그 원인 최소화

[세팅할 것]
1) index.html 파일 생성 (CSS 인라인, JS 인라인)
2) JSON 로드 및 파싱 함수
3) 기본 UI 레이아웃 (입력부 / 결과부 2단 구성)

아직 검증 로직은 구현하지 마. 뼈대만 잡아줘.
```

## STEP 2. 입력 UI 구현

```
입력 UI를 구현해줘. 검증 로직은 아직 구현하지 마.

[입력 항목]
1. 장 선택: 드롭다운 (1장 비타민미네랄 / 2장 해열진통제 / 3장 감기약 / 7장 진해거담제 / 9장 비염용경구제)
2. 제형 선택: 드롭다운 (해당 장의 허용 제형 목록을 JSON에서 로드)
3. 대상 연령: 드롭다운 (해당 장의 연령구분계수 목록을 JSON에서 로드)
4. 성분 입력부:
   - 성분 추가 버튼 클릭 시 행 추가
   - 각 행: [구분 드롭다운(해당 장의 항목)] [성분명 드롭다운(선택한 구분의 성분 목록)] [1일 배합량 입력(숫자)]
   - 성분명 드롭다운은 구분 선택에 따라 동적으로 변경
   - 행 삭제 버튼

[핵심 원칙]
- 드롭다운 옵션은 모두 JSON에서 동적으로 생성할 것 (하드코딩 금지)
- 장을 변경하면 하위 드롭다운이 모두 리셋될 것
```

## STEP 3. 핵심 검증 로직 구현 (함량 검증)

> **이 단계가 가장 중요합니다. 한 번에 전부 구현하지 말고, 장별로 나눠서 요청하세요.**

### STEP 3-1. 제1장 비타민미네랄 검증

```
제1장 비타민미네랄의 함량 검증 로직을 구현해줘.

[검증 규칙 — JSON의 "제1장_비타민미네랄" 섹션 참조]

A) 개별 성분 범위 검증:
   - 각 성분의 1일 배합량이 표1~표4의 최소분량 이상, 최대분량 이하인지
   - 단위 주의: IU, mg, μg, g이 혼재함

B) 연령계수 적용:
   - 만 8세 미만 어린이: 표5의 연령구분계수를 곱한 값이 최대/최소분량
   - 제형(추어블정/정캅셀환제/기타)에 따라 계수가 다름
   - 비타민A/D 함유 시 괄호 안 계수 적용
   - 미네랄: 표5 하단의 미네랄 연령별 최대분량 별도 적용
   - 만 8세 미만 어린이: 염소, 크롬, 망간, 몰리브덴, 칼륨, 나트륨, 황 배합 불가

C) 동일 항목 합산 검증:
   - 같은 항목(예: Ⅰ항 비타민A) 내 여러 성분을 배합할 경우
     → 합산량이 해당 항목의 1일 최대량을 넘지 않아야 함

[출력]
- 각 성분별: 적합 ✅ / 부적합 ❌ + 사유
- 연령계수 적용 후 환산값 표시
- 전체 판정: 적합 / 부적합

먼저 이 로직만 구현하고 테스트해줘. 
테스트 케이스: 비타민A(레티놀아세테이트) 5000IU + 비타민C(아스코르브산) 600mg + 칼슘 500mg, 성인, 정제
```

### STEP 3-2. 제2장 해열진통제 검증

```
제2장 해열진통제의 함량 검증 로직을 구현해줘.

[검증 규칙 — JSON의 "제2장_해열진통제" 섹션 참조]

A) 개별 성분 범위:
   - 1회 최대분량, 1일 최대분량 모두 검증
   - Ⅰ항 1종 배합 시: 1회량 하한 = 1회 최대분량의 1/2
   - Ⅰ항 2종 이상 배합 시: 각 1회량 하한 = 1회 최대분량의 1/5

B) Ⅰ항 2종 이상 배합 시 비례배합 검증:
   - 각 성분의 (배합량 / 1회최대분량) 합산값이 1/2 이상 3/2 이하

C) 이부프로펜(Ⅱ항)은 Ⅰ항과 배합 불가

D) 연령계수: 표3 적용
   - 아스피린, 아스피린알루미늄, 살리실산나트륨 함유 시 만 15세 미만 불가

[테스트 케이스]
아세트아미노펜 500mg/회 + 카페인무수물 50mg/회, 1일 3회, 성인, 정제
```

### STEP 3-3 ~ 3-5. 나머지 장

```
동일한 패턴으로 제3장/제7장/제9장 검증 로직을 구현해줘.
JSON의 해당 장 기준 섹션을 참조하고, 특히 다음에 주의:

- 제3장: 한약처방(라란) 배합 시 1/5~1/2 범위 제한, 마황과 Ⅴ-1항 배합 불가
- 제7장: 트로키제 전용 성분(9항), 가란은 2항/4항과 배합 불가
- 제9장: Ⅱ란 2종 배합 시 합산비 2 초과 금지, Ⅰ란 2항(메퀴타진)은 Ⅵ란 생약과 배합 불가

각 장마다 테스트 케이스 1개씩 포함해줘.
```

## STEP 4. 효능효과 자동 생성

```
입력된 성분 조합에 따라 효능효과 문구를 자동 생성하는 기능을 구현해줘.

[로직]
- JSON의 각 장별 "효능효과" 또는 "표6_효능효과" 데이터를 참조
- 성분 포함 여부에 따라 해당 효능효과 문구를 포함/제외

[장별 규칙]

1장 비타민미네랄:
  - 비타민A 2000IU 이상 → 표6의 비타민A 효능효과 기재
  - 비타민D 200IU 이상 → 표6의 비타민D 효능효과 기재
  - (나머지도 JSON의 "1일_보급량_기준_기재조건" 참조)
  - 칼슘 300mg 이상 → "칼슘결핍 및 기타 칼슘의 보급"
  - 철 18mg 이상 → "철 결핍성 빈혈의 예방 및 치료"
  - (나머지 추가효능도 JSON 참조)

2장 해열진통제:
  - 기본: "두통, 치통, ... 진통 / 오한, 발열시의 해열"

3장 감기약:
  - 기본: "감기의 제증상의 완화"
  - 단, Ⅲ항/Ⅵ항 미포함 시 "콧물, 코막힘, 재채기" 효능 불가
  - Ⅳ항/Ⅴ항/가란 미포함 시 "기침" 효능 불가
  - 가래 관련 성분 미포함 시 "가래" 효능 불가

7장 진해거담제:
  - JSON의 "효능효과_조건" 참조하여 기침/가래/천식 각각 판정

9장 비염용경구제:
  - "코감기, 알레르기성 비염 또는 부비동염에 의한 증상의 완화"

[출력 형태]
- 기재 가능한 효능효과 문구를 완성된 문장으로 출력
- 기재 불가 항목은 회색 취소선으로 표시 + 사유
```

## STEP 5. 사용상의 주의사항 자동 생성

```
입력된 성분에 따라 사용상의 주의사항을 자동 생성해줘.

[로직]
- JSON의 각 장별 "사용상의_주의사항" 데이터를 참조
- 각 주의사항 문구에 괄호로 표시된 조건(예: "아세트아미노펜 함유제제", 
  "감초 함유제제", "철분 함유제제" 등)을 파싱
- 입력된 성분 목록과 매칭하여 해당하는 주의사항만 출력

[매칭 규칙]
- "(아세트아미노펜 함유제제)" → 입력 성분에 아세트아미노펜이 있으면 포함
- "(비타민 D 또는 칼슘 함유제제)" → 비타민D 계열 또는 칼슘이 있으면 포함
- "(미네랄 함유제제)" → 표2 미네랄 중 아무거나 있으면 포함
- 조건 괄호가 없는 문구 → 무조건 포함 (공통 주의사항)
- "(감초 함유제제)" → 감초 또는 글리시리진산 함유 시 포함

[출력 형태]
- 카테고리별 구분: 경고 / 복용금지 / 병용금기 / 복용전상의 / 이상반응 / 기타주의 / 저장주의
- 각 항목 앞에 해당 조건 성분을 태그로 표시
```

## STEP 6. 결과 출력 및 내보내기

```
검증 결과를 보기 좋게 출력하고, 내보내기 기능을 추가해줘.

[결과 화면 구성]
1. 요약 패널: 전체 적합/부적합 판정 (큰 글씨, 색상)
2. 함량 검증 테이블: 성분별 배합량 / 기준범위 / 판정 / 연령계수 적용값
3. 효능효과 섹션: 기재 가능 문구 목록
4. 사용상주의사항 섹션: 카테고리별 해당 문구

[내보내기]
- "결과 복사" 버튼: 전체 결과를 클립보드에 텍스트로 복사
- "PDF 저장" 버튼: window.print() 활용한 인쇄용 레이아웃
```

## 버그 최소화 전략

| 전략 | 적용 방법 |
|------|-----------|
| **단계별 구현** | STEP별로 나눠서 요청 → 각 단계마다 테스트 후 다음 진행 |
| **데이터 분리** | 검증 로직에 숫자/문구를 하드코딩하지 않고 반드시 JSON에서 읽기 |
| **테스트 케이스** | 각 장마다 최소 2개 (적합 1개 + 부적합 1개) 테스트 요청 |
| **단위 통일** | mg/μg/IU/g 변환 함수를 별도로 만들어 일관 적용 |
| **에러 핸들링** | 빈 입력, 0 입력, 음수 입력에 대한 처리 요청 |

---

## 토큰 절약 팁

1. **한 번에 전체 구현 요청 금지** → 반드시 STEP별로 나눠서 요청
2. **JSON 파일은 처음 한 번만 읽게** → "이미 로드한 JSON을 참조해" 라고 명시
3. **이전 코드 반복 출력 방지** → "변경된 부분만 보여줘" 라고 명시
4. **기존 엑셀 분석은 STEP 0에서 1회만** → 이후는 정리된 규칙만 참조

터미널에서:
```bash
claude
```

VS Code 내장 터미널에서도 동일하게 실행 가능합니다.
(VS Code → Terminal → New Terminal → `claude` 입력)
