# 회귀 테스트 사용법

표제기 검토 툴의 **판정 결과가 바뀌지 않았는지** 확인하는 안전망입니다.

## 실행

로컬 서버로 `tests.html`을 엽니다. (파일을 직접 더블클릭하면 브라우저 보안 정책 때문에 iframe 내용을 읽지 못합니다.)

```bash
python -m http.server 7777
```

그다음 브라우저에서 `http://localhost:7777/tests.html` 로 접속합니다.

`.claude/launch.json`이 있으므로 Claude Code에서는 preview로 바로 띄울 수도 있습니다.

## 언제 돌리나

- **코드를 고친 직후** — 화면만 손봤다고 생각해도 한 번 돌려 보세요. 판정에 영향이 갔는지 바로 나옵니다.
- **표제기 개정 반영 후** — 바뀌어야 할 항목만 바뀌었는지 확인합니다.

> 캐시 때문에 옛 결과가 보이는 일이 없도록, 이 페이지는 `index.html`·`cases.js`·`baseline.js`를
> 매번 새로 읽습니다. 그래도 결과가 이상하면 `Ctrl+Shift+R`로 강력 새로고침하세요.

## 결과 읽는 법

| 표시 | 뜻 | 할 일 |
|---|---|---|
| **통과** | 판정이 이전과 같음 | 없음 |
| **실패** | 판정이 바뀜 | 의도한 변경인지 확인. 아니면 **버그** |
| **오류** | 실행 중 예외 | 코드가 깨졌거나 성분명이 표에 없음 |
| **신규** | 기준값이 없는 케이스 | 아래 "기준값 갱신" 참고 |

실패한 항목은 `기준값(이전)` / `현재 결과`를 나란히 보여줍니다.

## 파일 구성

```
tests.html          테스트 실행 화면 (index.html을 iframe으로 읽기만 함 — 수정하지 않음)
tests/cases.js      입력 케이스 + 성분명 매칭·장 추정 기대값(사람이 정한 값)
tests/baseline.js   판정 결과 기준값 스냅샷(현재 동작을 고정한 값)
tests/flows.js      전환 흐름 케이스 — 제품·장을 갈아끼울 때의 기대 동작
```

## 기준값 갱신

**표제기가 개정되어 판정이 의도적으로 바뀐 경우에만** 갱신합니다.

1. 실패 항목을 하나씩 열어 **개정 내용과 일치하는지 확인**
2. 페이지 하단 `[기준값 새로 저장]` 클릭
3. 출력된 내용으로 `tests/baseline.js` 전체를 교체
4. 다시 새로고침해서 전부 통과하는지 확인

> 확인 없이 갱신하면 버그를 정답으로 굳히게 됩니다. 이 단계를 건너뛰지 마세요.

## 케이스 추가

`tests/cases.js`의 `window.TEST_CASES`에 항목을 추가하고, 페이지를 새로고침하면
"신규"로 표시됩니다. 위의 기준값 갱신 절차를 거치면 고정됩니다.

성분명은 **표준제조기준 표에 적힌 그대로** 써야 합니다.
(예: 제7장의 거담제는 `구아이페네신`이 아니라 `△구아이페네신`)

연령 키는 장마다 표기가 다릅니다.
- 제1장: `만12세이상(성인)`, `만3개월이상_만12개월미만`, `만15세이상` …
- 제2·3·7·9장: `만 15세 이상`, `만 7세 이상 - 만 11세 미만` …

## 현재 담고 있는 것 (49건)

**판정 결과 32건** — 5개 장 전체
- 저장 DB의 **실제 검토 제품 7종**: 이브비듀얼·이브쎈듀얼·포에브밸런스(제2장, 연령 3구간),
  모드콜이부콜드(제3장, 연령 3구간), 비프리스트롱(제9장), 아이간유·챔큐비타젤리(제1장)
- 경계 케이스: 1일 최대 초과 / 최소 미달 / 연령계수 적용 / IU·μg 단위 /
  표3 기타성분 / 배합 규칙 위반(필수 성분 누락, Ⅰ란 필수)

**성분명 매칭 8건** — 완전일치, 괄호 별칭(`아미노에틸설폰산(타우린)` ↔ `타우린`),
표기 흔들림(`우르소` ↔ `우루소`), 그리고 **오탐 방지**(`염산염` ≠ `질산염`)

**적용 기준 자동 추정 3건** — 허가목록 성분으로 장 고르기, 대상 아닌 품목 판별

**전환 흐름 6건** — 제품·장을 갈아끼울 때 이전 상태가 남지 않는지
- 장이 다른 제품으로 왕복 / 같은 장의 다른 제품(성분 섞임 방지)
- 첨가제·연령 선택이 이전 제품 것으로 남지 않는지
- 작업자가 직접 고른 장은 유지되는지 / 안내 문구가 이전 제품 것으로 남지 않는지

> 판정 결과 테스트는 "값을 넣으면 올바른 답이 나오는가"를 보고,
> 전환 흐름 테스트는 "화면을 갈아끼울 때 이전 내용이 섞이지 않는가"를 봅니다.
> 성격이 달라 둘 다 필요합니다.

## 알아둘 점

- 기준값은 **"지금 코드가 내는 답"**이지 **"고시가 정한 정답"**이 아닙니다.
  처음 한 번은 담당자가 고시와 대조해 검토해 주세요.
- 테스트는 **검증 로직만** 봅니다. 화면 레이아웃·색상은 대상이 아닙니다.
